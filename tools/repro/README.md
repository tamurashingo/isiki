# cc_car/cc_cdr インライン化ハングの再現

## これは何か

`cc_car`/`cc_cdr`(生成コード中2,784箇所)を `static inline` にすると、
`init.lisp` の `(defun make-environment (name &rest parent-env) ...)` を
JITコンパイルする途中で**無限ループに入る**。コードは1バイトも出ず、
確保だけが続く。根本原因は**特定済み**(同日): JIT生成コードが callee-saved の r14 を復元していなかった。`documents/pitfalls.md` 原則11 参照。

## 再現手順

    tools/repro/cc_car_hang.sh

やっていること:

1. `tools/repro/cc_car_inline.patch` を当てる(cc_car/cc_cdrをstatic inline化)
2. **za.c の上限コード/カウンタ類を無効化する**(後述)
3. `make test-qemu` を走らせる。ハングすれば再現

**修正後(r14 の退避/復元を入れた HEAD)では「完走した(再現せず)」と出るのが正しい。**
ハングしたら回帰である。

## 重要: 上限コードを外さないと再現しない

za.c には無音ハング対策として3つの上限がある。

  ZA_MAX_MACROEXPAND_ITER   za_macroexpandの反復
  ZA_MAX_ANALYZE_STEPS      za_analyze_var_usageのステップ
  ZA_MAX_BODY_FORMS_WALK    letのbody走査(+ Floydの循環検出)

**これらを入れると、上限が一度も発火しないままハングが消える。**
実測(2026-09-13):

| インライン | 追加コード | 上限値 | 結果 |
|---|---|---|---|
| なし | — | — | 通過 |
| あり | なし | — | **ハング** |
| あり | カウンタ+上限 | 10000等 | 通過(発火0) |
| あり | カウンタ+上限 | 10^12(無効) | 通過 |
| あり | メモリバリアのみ | — | **ハング** |

| あり | グローバル宣言のみ(未使用) | — | **ハング** |

読み取れること:

- 上限の**値**は無関係(条件4)
- **純粋な最適化バリアでは効かない**(条件5) -> 最適化可視性の問題ではない
- **グローバルを宣言するだけでも効かない**(条件6) -> .bssのレイアウトでもない

効いているのは**関数の中で実際に実行されるコード**(ローカル変数・分岐)である。
スタックフレームのレイアウトと制御フローに敏感、という形になる。
これは「初期化されていない、または範囲外のスタック読み出し」の症状と整合する。

## GC圧を上げたいとき

`QEMU_MEM` を下げる。**生成コードを一切変えずにGC頻度を上げられる**唯一の手段
(`%%DIAG-GC-STRESS` は GC_DEBUG 専用で、GC_DEBUG は cc_car 内に呼び出しを入れて
インライン化自体を消してしまう)。

| -m | 全件のGC回数 |
|---|---|
| 256M(既定) | 2 |
| 128M | 12 |
| 96M | 19 |
| 80M | 52 |
| 72M以下 | 起動しない |

## 関連する未解明の1件

`za_compile_let` のループ上限 `r8 = 0x449AA7E0` がゴミになった件(2026-09-12)も、
機序を特定できないまま `init_forms`/`operand_forms`/`arg_forms` の保護追加で消えた。
**どちらも za.c のループ上限まわりで、ゴミが入り、無関係な変更で消え、機序が未特定。**
レイアウト摂動に敏感という点で同じ根の可能性がある。3件目が出たら並べて見ること。
