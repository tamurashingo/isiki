# 比較演算の型特化(#128 / M7 の残り)

> 状態: **single float の比較を実装する前の宣言(2026-11-03)。** 実測は §5。

## 1. 現状 — **比較の特化関数は 1 つも無い**

四則には `_fixnum` と `_single` が揃っているのに、比較には**何も無い**。数えた:

| | `_fixnum` | `_single` |
|---|---:|---:|
| `+` `-` `*` `/` | **あり**(各 1) | **あり**(各 1) |
| `<` `>` `<=` `>=` `=` `/=` | **0** | **0** |

## 2. 配線は既にある — **表に載っていないだけだった**

`za_specialized_wrapper`(`za.c`)が GENERIC の関数ポインタで振り分ける。
比較は `za_compile_binary` を通り、**そこが既にこの振り分けを呼んでいる**:

```c
/* za.c:3699 付近。za_compile_binary の中 */
void *specialized = za_specialized_wrapper(wrapper_fn, 型a, 型b);
if (specialized != 0) { wrapper_fn = specialized; }
```

既存のコメントにこう書かれている:

> `za_specialized_wrapper` は GENERIC の関数ポインタで振り分けるので、
> **比較演算子が誤って差し替わることはない(表に載っていないので 0 が返る)**

**つまり新しい経路は要らない。特化関数を書いて表に足すだけである。**

## 3. どこに得があるか — **single だけ**

宣言できる型は **`<fixnum>`(20)と `<single-float>`(22)の 2 つだけ**である。

| 特化 | 得 | 理由 |
|---|---|---|
| **`<single-float>`** | **大きい** | いまは `num_both_nonneg_fixnum` を外れて `primitive_*_slow` → **`number_compare4`**(汎用)へ落ちる。single は**即値**(`TAG_SINGLE_FLOAT = 0x4`、ポインタでない)なので、直接取り出して比べれば汎用を丸ごと飛ばせる |
| `<fixnum>`(非負) | **ほぼゼロ** | 特化しても**符号の検査は外せない**。fixnum は**符号＋絶対値**で、`(declare (type <fixnum>))` でも負値は来る。生のタグ付き値を比べると負値は巨大な正の値に見える。節約はタグ検査が消える分だけで、命令数は変わらない |
| `<fixnum>`(負値) | 大きい | いまは `number_compare4` へ落ちる。符号＋絶対値で直接比べられる |

**この PR は single だけを入れる。** fixnum は符号＋絶対値の機微があるので別 PR にする
(状態の数 = 変更の数 + 1)。

## 4. NaN — **C の比較演算子と意味論が一致する**

ここが唯一の危ない所なので先に確かめた。

`number_compare4` は **4 値**を返す(`LESS` / `EQUAL` / `GREATER` / **`UNORDERED`**)。
三値だと NaN を表せず `(= nan nan)` が真になっていたのを PR #85 で直した
(`documents/nan-comparison.md`)。述語はその 4 値の上に作られている:

| 述語 | 汎用の定義 | NaN のとき | C の演算子 | 一致 |
|---|---|---|---|---|
| `<` | `compare4 == LESS` | 偽 | `a < b` → 偽 | **する** |
| `>` | `== GREATER` | 偽 | `a > b` → 偽 | **する** |
| `<=` | `== LESS \|\| == EQUAL` | 偽 | `a <= b` → 偽 | **する** |
| `>=` | `== GREATER \|\| == EQUAL` | 偽 | `a >= b` → 偽 | **する** |
| `=` | `== EQUAL` | 偽 | `a == b` → 偽 | **する** |
| **`/=`** | `num_ne`(**非順序で真**) | **真** | `a != b` → **真** | **する** |

**4 値の論理は IEEE に合わせて作られているので、C の比較演算子がそのまま同じ答えを出す。**
`/=` が非順序で真になる唯一の比較である点も `!=` と一致する
(`runtime.c` の註: 「`num_lt(a,b) || num_gt(a,b)` と書くと非順序がどちらにも該当せず
偽になり、IEEE 754 に反する」)。

> **一致することを導いたうえで、6 つすべてに NaN の試験を置く。**
> 導出が合っていても、書き間違いは試験でしか捕まらない。

## 5. 測る前の宣言(規則 11・14)

**R-path: JIT のみ**(AOT は宣言を扱わない。インタプリタは対象外)。

### R-set — **記録されている 29 行は 1 行も動かない**(断言)

| 行 | 動くか | 理由 |
|---|---|---|
| `c/*` 10 行 | **動かない** | 素の C。Lisp の経路を通らない |
| `aot/*` 10 行 | **動かない** | AOT は `declare` を扱わない |
| `jit/*` 6 行 | **動かない** | **ベンチの関数は `declare` を書いていない**ので特化版が選ばれない |
| `interp/*` 3 行 | **動かない** | インタプリタは特化版を使わない |
| 命令数ゲートの既存 11 区間 | **動かない** | 比較の区間が 1 つも無い |

**つまり記録されている計測では効果が 1 つも見えない。** だから区間を足す。

### 足す区間と予測

| 区間 | 中身 | 予測 |
|---|---|---|
| `<sgl-nodecl` | 宣言なしの `(< x y)` に single を渡す | **対照。動かない** |
| **`<sgl-decl`** | `(declare (type <single-float> ...))` つき | **速くなる。** `number_compare4` の呼び出しが消える |
| `<fix-decl` | fixnum 宣言つき(非負の値) | **対照。動かない**(§3 の導出) |

★ 幅は宣言しない。`number_compare4` の 1 回あたりの費用を測っていないため。
**代わりに機構を宣言する**: 速くなるとすれば
**`primitive_*_slow` と `number_compare4` の呼び出しが消えたぶん**である。
`<sgl-decl` が動かなければ、特化版が選ばれていない(= 配線の理解が間違っている)。

確保量: **1 byte も動かない**(断言)。比較は物体を作らない。

## 6. 実測(2026-11-03)— **宣言は 2 つとも当たった**

```
make test-qemu-instcount-gate MILESTONE=test/lisp/qemu_boot_inline_phase3.lisp
```

| 区間 | per-call | 宣言 | 判定 |
|---|---:|---|---|
| `<sgl-nodecl`(対照) | **209.94** | — | — |
| **`<sgl-decl`** | **23.94** | 速くなる | **当たり。−186.00(8.8 倍速)** |
| `<fix-nodecl`(対照) | 26.94 | — | — |
| `<fix-decl` | **26.94** | **動かない** | **当たり。±0.00** |
| 既存 10 区間 | 21.94 / 26.94 / 21.94 / 22.94 / 27.94 / 22.94 / 33.94 / 30.94 / 24.94 / 475.95 | 動かない | **全て ±0.00** |

全区間 **gc=0**。既存 10 区間は A(PR #152)の後の記録値と**完全に一致**した。

### `<sgl-nodecl` は 2 番目に高い区間だった

210 命令は `+dbl-decl`(475.95)に次ぐ。**宣言の無い single どうしの比較が、
加算より 8 倍以上高かった。** 内訳は導出どおり:

    num_both_nonneg_fixnum を外す(タグ 0x4)
      -> primitive_less_than2_slow(noinline, cold)への call
        -> number_compare4(4 値の汎用比較)への call

特化版はこの 2 段の call を消して即値から直接比べる。**23.94 は `+sgl-decl`(24.94)より
1 命令低く**、辻褄が合っている(比較は結果を箱に入れないので加算より 1 つ少ない)。

### fixnum は**動かない**と宣言して、動かなかった

`<fix-decl` 26.94 = `<fix-nodecl` 26.94。**±0.00。**
導出(§3)のとおりで、**fixnum は符号＋絶対値なので `(declare (type <fixnum>))` でも
負値は来る**。符号の検査は外せず、節約はタグ検査の分だけなので命令数は変わらない。

> **「特化すれば速くなる」は型によって成り立たない。**
> single が 8.8 倍速くなったのは特化したからではなく、
> **特化する前の経路が汎用の 4 値比較まで落ちていたから**である。
> fixnum は最初から常道に乗っていたので、特化しても行き先が同じだった。

### この PR では得をしない経路(正直に書く)

- **double の比較は速くならない。** 宣言できる型は `<fixnum>` と `<single-float>` の
  2 つだけで、`<double-float>` の比較の特化版は作れない
  (`OS_DECL_TYPE_*` に double が無い)
- **`src/lisp/mandelbrot.lisp` も速くならない。** 浮動小数を多用し `>` で比較するが、
  (1) 型宣言を書いていない (2) 既定の float は double である。
  **宣言を書き、かつ single にすれば効く**見込みだが、それは別の作業である

## 7. 途中で間違えたこと

### コード長は切り替わりの計器にならない

試験に「宣言つきと宣言なしで生成コードの長さが違えば差し替わっている」と書いた。
**成立しない。** 呼び出しの出力は

```
movabs r11, <呼び先のアドレス>   ; 10 byte(即値が変わるだけ)
call   r11                        ;  3 byte
```

で、**呼び先が変わっても命令長は 1 byte も変わらない**(実測 871 対 871)。
既存の「切り替わったことを別の計器で確認してから測る」作法を真似たつもりが、
**選んだ計器がその差を見られないもの**だった。

試験はこれを捕まえた(`53 passed, 1 failed`)。いまは「長さが**同じ**であること」を
事実として固定してある(呼び出しの出し方が変わったら落ちる)。
**切り替わりの証拠は命令数で取る。**

### 区間を足して期待値を更新し忘れた

`%%GATE-HITS` の期待値(12)を直さずに区間を足したのでゲートが落ちた。
4 区間足したので **16** へ、理由つきで更新した(規則 9)。
**落ちたのは正しい**: 区間の数が合わないまま測ると、どの区間を測ったのか分からない。

## 8. 嘘の宣言が監査ビルドで捕まる(陽性対照)— **切り替わりの証拠にもなった**

```
make test-qemu-milestone EXTRA_CFLAGS=-DISIKIOS_DECLARE_AUDIT MILESTONE=<嘘をつく milestone> \
  QEMU_EXTRA_FLAGS="-serial file:$PWD/tmp/lie.serial.txt"
```

single を宣言した比較に fixnum を渡した結果(シリアル):

```
PANIC: declare が嘘をついている
  関数: primitive_less_than2_single
  宣言された型: <single-float>
  実際のタグ: 0x0 (0=fixnum 4=single-float 7=instance)
PANIC: declare audit: 宣言と実際の型が一致しない
```

**診断に関数名 `primitive_less_than2_single` が出ている。**
つまりこの 1 回で 2 つ示せた:

1. **嘘の宣言が捕まる**(Issue #128 が要求する陽性対照)
2. **特化版が実際に呼ばれている**(§7 でコード長では見られなかった切り替わりの証拠)

### **シリアルを捕まえないと、この対照は成立しない**

最初は `-serial` を付けずに走らせ、「2 回とも結果を出しませんでした」で終わった。
**panic と整合はするが証拠にならない。** 電源が切れて `test-results.txt` が
書かれないので、**PR #151 で族として扱った「結果が無い」flake と外から見て
区別がつかない**(`documents/heap-exhaustion.md` と同じ罠)。

> **落ちることを見せる手段は、落ち方によって変わる。**
> ビルドで落ちる検査(`_Static_assert`)は `make` の失敗として、
> panic で落ちる検査はシリアルの診断として捕まえる。
> **「落ちた」だけでは、何が落ちたか分からない。**
