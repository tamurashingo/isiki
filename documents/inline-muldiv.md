# `*` `/` のインライン展開(#128 / M7-T1)

> 状態: **実装前の宣言(2026-11-07)。** 実測は §5。

## 1. 現状 — ビットは立つのに誰も見ていない

| | 状態 |
|---|---|
| `INLINE_BIT_MUL` / `INLINE_BIT_DIV` の定義 | **ある**(`runtime.h`。bit 6 / 7) |
| `(declare (inline *))` が立てるか | **立てる**(`runtime.c` の `g_inline_names` に `*` `/` がある) |
| `za.c` が見ているか | **見ていない**。`za_inline_enabled` を呼ぶのは ADD / SUB / NULL / EQ だけ |

**つまり宣言は通るのに何も起きない。** `*` `/` は常に呼び出しになる。

## 2. 設計上の要点 — **`mul` / `div` は `rdx` を壊す**

既存の `za_emit_arith_call_or_inline` は、こう書かれた前提に乗っている:

> フォールバック: **rcx=a, rdx=b は上記のいずれの分岐でも変更していない**ため、
> 従来通り `wrapper_fn(a, b)` をそのまま間接 call できる。

ところが x86 の 1 オペランド形式は:

```
mul  r64   ; rdx:rax = rax * r64   ← rdx を必ず書く
div  r64   ; rax = rdx:rax / r64、rdx = 余り  ← rdx を必ず書く
```

**`b` を持つ `rdx` が消える。** そこで:

- `b` を **R8**(この関数では未使用)へ退避する
- 桁あふれ / ゼロ除算でフォールバックする経路は、**復元用スタブ**
  (`mov rdx, r8`)を通してから共通のフォールバックへ落ちる
- **add / sub の経路は一切触らない**(スタブは `*` `/` のときだけ出す)

## 3. 出す命令

### `*`(両方非負 fixnum が保証された後)

```
mov  r8,  rdx         ; b を退避
mov  rax, rcx
shr  rax, 4           ; magnitude(a)
mul  r8               ; rdx:rax = magnitude(a) * b
test rdx, rdx         ; 上位 64bit が非零 = 桁あふれ
jne  -> 復元
test rax, rax
js   -> 復元          ; bit63 が立った = 59bit を超えた
```

**`(a >> 4) * b` にするのは、タグ付きのまま掛けると 2 回ぶんずれるから**である
(`(ma<<4) * (mb<<4) = ma*mb<<8`)。片方だけ戻せば `ma*mb<<4` になる。

**桁あふれは 2 つ見る。** 上位 64bit(`rdx`)と bit63 の両方である。
`__builtin_mul_overflow` と bit63 を両方見ている A の `fixnum_fast_mul` と同じ理由で、
**生の 64bit 乗算が巻き上がると符号 bit だけでは分からない**。

### `/`

```
mov  r8,  rdx         ; b を退避
test r8,  r8
je   -> フォールバック ; **ゼロ除算の検査は外せない**(#DE で機械が止まる)
mov  rax, rcx
xor  rdx, rdx         ; 被除数の上位を 0 に
div  r8               ; rax = a / b
shl  rax, 4           ; タグを戻す
```

`(ma<<4) / (mb<<4) = ma/mb` でシフトが打ち消えるので、`<< 4` で戻す。
**商は被除数を超えないので桁あふれの検査は要らない。**

## 4. 測る前の宣言(規則 11・14)

**R-path: JIT のみ。** AOT は宣言を扱わず、インタプリタは対象外。

### 宣言制御である — **宣言が無ければ従来どおり**

`+` `-` は**宣言が無くても常に展開される**が、`*` `/` は
**`(declare (inline *))` があるときだけ**展開する。
宣言なしの経路を触らないので、R-set が狭いままになる。

### R-set

| 区間 / 行 | 動くか | 理由 |
|---|---|---|
| **`*fix-inline`**(新設) | **速くなる** | 宣言つき。展開される |
| **`/fix-inline`**(新設) | **速くなる** | 同上 |
| `*fix-decl` / `/fix-decl` | **動かない** | `inline` 宣言が無いので従来どおり呼び出し |
| `+fix-*` / `-fix-*` / `<*` / `+sgl` / `+dbl` の 14 区間 | **動かない** | 経路を触らない |
| ベンチ 29 行 | **動かない** | 測定対象 10 区分は `*` `/` を使わない(PR #163 で数えた) |

### 幅の予測

いま `*fix-decl` は 33.94、`/fix-decl` は 30.94 である。
呼び出し(`movabs` + `call` = 2)と呼び先(`*` は 22 命令、`/` は 19 命令)が
展開(`*` は 8、`/` は 7)に置き換わる:

| | 宣言 |
|---|---|
| `*fix-inline` | **−8 〜 −14**(予測 −11) |
| `/fix-inline` | **−6 〜 −12**(予測 −9) |

★ 前提: 守りの 5 命令は add / sub と共通なので差に出ない。

### **`/` は命令数ほど速くならない**(先に書いておく)

`div` は 20〜40 サイクルかかる。**命令数は下がるが、壁時計の改善は命令数の比ほど
大きくない。** 命令数ゲートは命令を数える計器なので、
**この差は計器に出ない**。ここに書いておく。

確保量: **1 byte も動かない**(断言)。展開は確保を伴わない。

## 5. 実測(2026-11-07)— **幅を 2 つとも外した(過大評価)**

| 区間 | 対照 | 展開後 | 差 | 宣言 | 判定 |
|---|---:|---:|---:|---|---|
| **`*fix-inline`** | 33.94 | **29.94** | **−4.00** | −8 〜 −14 | **外した** |
| **`/fix-inline`** | 30.94 | **28.94** | **−2.00** | −6 〜 −12 | **外した** |
| `*fix-decl` / `/fix-decl` | 33.94 / 30.94 | 同じ | ±0.00 | 動かない | **当たり** |
| `+fix-*` / `-fix-*` / `<*` / `+sgl` / `+dbl` | — | — | ±0.00 | 動かない | **当たり** |

生成コードの長さ(展開されたことの裏): `*` 871 → **950**、`/` 871 → **944**。

### 外した理由 — **関数の大きさを、呼ぶ費用として使った**

見積もりはこう立てた:

> 呼び出し(`movabs` + `call` = 2)と**呼び先**(`*` は **22 命令**、`/` は **19 命令**)が
> 展開(`*` は 8、`/` は 7)に置き換わる

**22 / 19 は関数全体の命令数である。** 実際に払うのは**常道だけ**で、
`primitive_multiply2_fixnum` の常道は
`num_both_nonneg_fixnum` + `fixnum_fast_mul` + return ≈ **10 命令**しかない
(残りは `_slow` 側で、桁あふれしない限り通らない)。

    実際の差 = (呼び出し 2 + 常道 ≈ 10) − 展開 ≈ 8  =  −4   ← 実測と一致

> **関数の命令数は、その関数を呼ぶ費用ではない。**
> 払うのは**常道の長さ + call/ret** である。
> **A で「冷たい経路を別関数に出す」ことをやったのは自分なのに、
> その結果として「関数の大きさ」と「通る道の長さ」が乖離したことを
> 見積もりに反映していなかった。**

#### このセッションで同じ形の外しを 6 回している

| | 取り違えたもの |
|---|---|
| M7 | 呼び先の連鎖を数え忘れた |
| A | 呼び出し側の列を数え忘れた |
| 陽性対照の桁 | 計器が見ている**範囲**(`os_eval` 区間 vs 総命令数) |
| `os_eval` の費用 | 1 回あたりの**大きさ** |
| 捕捉解析の R-set | 判定の**代用**(構文で数えた) |
| **ここ** | **静的な大きさ vs 実際に通る道** |

**関係として宣言した 2 回**(`Δos_make_cons = 2 × Δ可変長呼び出し`、
`interp/loopcost − interp/loop ≒ interp/let − interp/arith`)は**どちらも当たっている**。

### 費用と釣り合い(正直に書く)

| | 得 | 払うもの |
|---|---|---|
| `*` | **−4 命令/呼び出し** | 生成コード **+79 byte**/箇所 |
| `/` | **−2 命令/呼び出し** | 生成コード **+73 byte**/箇所 |

**釣り合うのはホットループの中だけ**である。そしてそれは
**`(declare (inline *))` と書く人が意図している場所**なので、
宣言制御にした設計はここで効いている(宣言が無ければ 1 byte も増えない)。

### `/` は命令数ほど速くならない(宣言どおり)

`div` は 20〜40 サイクルかかる。**命令数は −2 だが、壁時計の改善はそれ以下**である。
命令数ゲートは命令を数える計器なので**この差は計器に出ない**。
先に書いておいたとおりで、ここでも成立している。

## 6. 途中で間違えたこと — **`/` は別の経路を通っていた**

最初の実装では **`*` だけ展開され、`/` は展開されなかった**
(生成コードの長さ 871 → 950 / 871 → **871**)。

`za_emit_arith_call_or_inline` は **`za_compile_fold` からしか呼ばれていない**が、
**`/` は `za_compile_binary` を通る**(既存のコメントに
「`za_compile_fold` と同じ仕組みだが、**`/` はこちらを通る**」と書かれていた)。

`za_compile_binary` の呼び出し箇所を共通の出し方へ寄せて解決した。
**比較など対象外の呼び先は、その関数の中で `movabs` + `call` へそのまま落ちる**
ので振る舞いは変わらない(`rcx`=第一 / `rdx`=第二 の規約も fold と同じ)。

> **試験が「展開されたか」を見ていたから気づけた。**
> 答えだけを見ていたら、`/` が展開されていないことに気づかないまま
> 「`*` `/` のインライン展開を入れた」と書いていた。
> **比較の特化(#162)ではコード長が計器にならなかったが、
> 展開は命令の数そのものが変わるのでここでは使える** —
> 同じ道具が、変更の種類によって使えたり使えなかったりする。
