# JIT 生成コードを静的に読んで検査する(2026-10-04)

**実行して確かめられない不変条件を、生成された機械語を読むことで確かめる技法。**
`test/lisp/jit_frame_test.lisp` と `test/lisp/jit_rsp_balance_test.lisp` で使っている。

## 1. なぜ実行では確かめられないのか

JIT のスタックフレームに関する壊れ方は、**実行すると「落ちる」ではなく
「ハングする」**。

| 壊れ方 | 実行したときの症状 |
|---|---|
| フレームが太って再帰深さが減る | 上限を超えた呼び出しでガードページ #PF。シリアルに `** STACK OVERFLOW **` は出るが、その式は二度と評価されないので**外からは固まったようにしか見えない** |
| `sub rsp` と `add rsp` が食い違う | `ret` のとき `rsp` がずれ、**戻り番地でないものへ飛ぶ**。どこで壊れたか分からない暴走 |

**テストフレームワークは「落ちた」ことを報告できない。** 報告する前にプロセスが
死んでいるか、報告する処理そのものが壊れたスタックの上で動くことになる。

> 深さを直接探ってはいけない。**探ること自体が壊す。**

## 2. 代わりに読む

JIT 済み関数からは、カーネルに手を入れずに機械語が読める。

| 使うもの | 何が得られるか |
|---|---|
| `%%DISASM-CODE-BASE` | 生成コードの先頭アドレス(JIT 化されていなければ `nil`) |
| `%%DISASM-CODE-LEN` | そのバイト長 |
| `%%DISASM-ITEM` | `(長さ 種別 ニモニック オペランド バイト列 整形済み1行 注釈)` |
| `%%PEEK` | 1 byte 読み |
| `%%POKE` | 1 byte 書き(**陽性対照のためだけに使う**) |

**どれも常時登録されていて、GC_DEBUG 限定ではない。**

### 2-1 命令の長さは自前のデコーダに数えさせる

**バイト列を素で走査してはいけない。**

```
movabs r11, 0x00007f48_81ec1d38      ; この即値の中に 48 81 EC が現れる
```

`sub rsp, imm32` は `48 81 EC` + imm32 だが、**`movabs` の 8 byte 即値や
埋め込み文字列の中に同じ並びが現れうる。** 素の走査はそれを命令と誤認する。

`%%DISASM-ITEM` は `src/c/disasm.c`(ランタイムに依存しない純粋なデコーダ)を
呼んで**命令の長さ**を返す。これで歩けば命令境界を外さない。

```lisp
(while (< off len)
  (let ((it (%%disasm-item base len off)))
    (if (null it)
        (setq off len)                       ; 範囲外 = 終端
      (progn
        ;; … off の位置を調べる …
        (setq off (+ off (car it)))))))      ; car = 命令の長さ
```

**値そのものはバイトで読む。** デコーダが返すオペランドは整形済みの文字列
(`"rsp, 0x1d38"`)なので、数値として比べるには `%%PEEK` で imm32 を組み立てるほうが
素直である。**境界はデコーダ、値はバイト。**

### 2-2 x86-64 の該当エンコーディング

| 命令 | バイト列 |
|---|---|
| `sub rsp, imm32` | `48 81 EC` + imm32(リトルエンディアン) |
| `add rsp, imm32` | `48 81 C4` + imm32 |
| `sub rsp, imm8` | `48 83 EC` + imm8 |
| `add rsp, imm8` | `48 83 C4` + imm8 |

**imm8 形式は数えない。** `jit_call_r11` が `call` の前後で `sub rsp, 0x20` /
`add rsp, 0x20` を対にして出す Microsoft x64 ABI の shadow space であり、
フレームとは別の話である(`jc-plain` 1 本で 19 対あった)。

## 3. 不変条件 — **値の一致だけでは足りない**

### 3-1 怖い故障は 2 種類ある

| | 故障 | どう壊れるか |
|---|---|---|
| **A** | **値が違う** | `sub` と `add` の即値が食い違う |
| **B** | **命令が無い** | 出口の 1 つで `add rsp` を**出し忘れる** |

**実寸化のような変更で起きるのは (B) のほうである。** 出口ごとに「この経路では
何 byte 戻すか」を判断する形になるので、**判断漏れ = 命令が出ない。**

> **値の一致は、存在しない命令を見られない。**
> この検査の初版は (A) だけを見ていて、陽性対照も (A) 側(即値を 1 byte 変える)で
> 取っていたので、**穴が見えていなかった。**

### 3-2 (A): 即値が全部同じ 1 つの値であること

`ZA_FRAME_TOTAL` の `sub`/`add` の出力箇所(`za.c`):

| | 箇所 | どこで出るか |
|---|---:|---|
| `jit_sub_rsp_imm32` | 2 | プロローグ(cons ABI の入口と固定引数の入口) |
| `jit_add_rsp_imm32` | 3 | エピローグ 1 + **末尾呼び出しの経路 2**(本体のコンパイル中) |

### 3-3 (B): `pop r13` を出口の道標にする

`jit_pop_r13()` の呼び出しは **3 箇所しかなく、いずれも
`jit_add_rsp_imm32(ZA_FRAME_TOTAL)` の直後**である。フレーム解体は必ず

```
add rsp, imm32 ; pop r13 ; pop rbx ; (ret または jmp)
```

の形で出る。だから次の 2 つで (B) を捕まえられる:

- **`add rsp, imm32` の個数 = `pop r13` の個数**
- **すべての `pop r13` の直前の命令が `add rsp, imm32` であること**(orphan = 0)

### 3-4 **どの 2 つの個数を比べるか**を間違えないこと

実測:

| 関数 | `sub` | `add` | `pop r13` |
|---|---:|---:|---:|
| `%jrb-leaf`(末尾呼び出しなし) | 2 | 2 | 2 |
| `%jrb-tail`(**末尾呼び出しあり**) | 2 | **4** | **4** |

**`sub` と `add` の個数は一致しない** — `sub` は入口ごと、`add` は出口経路ごと。
**`add` と `pop r13` は同じ 3 箇所から対で出るので一致する。**

> **「個数を数えるな」ではなく「どの 2 つを比べるか」である。**
> 本来の不変条件は「**生成関数のすべての出口が `rsp` を戻す**」。
> 経路解析は重いので `pop r13` を道標にした近似を使う。

### 3-5 imm8 形式は数えない

`jit_call_r11` が `call` の前後で `sub rsp, 0x20` / `add rsp, 0x20` を対にして出す
Microsoft x64 ABI の shadow space であり、フレームとは別の話である
(`%jrb-plain` 1 本で 19 対あった)。

## 4. 陽性対照 — **壊したコードは呼ばない。そして 2 種類壊す**

検査が効いていることを確かめるには、実際に壊す必要がある。
だが**呼べばテストごと死ぬ。** 静的に読むだけなので、安全に壊して戻せる。

### 4-1 (B) の対照: **命令を `nop` で潰す**

`add rsp, imm32` は 7 byte(`48 81 C4` + imm32)。全部 `0x90` にすると
「出し忘れた」のと同じ形になる。

```
#D tail/before    sub=2 add=4 bad=0 popr13=4 orphan=0
#D tail/NOPPED    sub=2 add=3 bad=0 popr13=4 orphan=1   ← 値の一致は通る
#D tail/restored  sub=2 add=4 bad=0 popr13=4 orphan=0
```

**`bad=0` のまま通る。** これが初版の穴で、`orphan` と個数の一致が捕まえる。
テストでは **`bad=0` が通ることも assert してある** — 穴を記録として残すため。

### 4-2 (A) の対照: **即値の 1 byte を変える**

```lisp
(defglobal jrb-poke-at (+ base (+ (%jrb-first-add-off f) 3)))   ; imm32 の最下位バイト
(defglobal jrb-saved-byte (%%peek jrb-poke-at))
(defglobal jrb-bump (%%poke jrb-poke-at (+ jrb-saved-byte 1)))
(assert-equal t (if (> (%jrb-bad f) 0) t nil))     ; 値の故障は捕まる
(assert-equal 0 (%jrb-orphan f))                    ; **解体の対は崩れない**
(defglobal jrb-unbump (%%poke jrb-poke-at jrb-saved-byte))
```

**A と B は別の故障である** — 片方の対照では、もう片方の検査を確かめられない。

### 4-3 壊す場所

どちらも **末尾呼び出しを含む関数の最初の `add rsp, imm32`**。エピローグより先に
出力されるので、**末尾呼び出しの経路そのもの**である。

戻したあとに「orphan 0」「個数一致」「実際の呼び出し」の 3 つを置いて、
**戻し忘れも落とす。**

## 5. この技法が向くもの / 向かないもの

| | |
|---|---|
| **向く** | 生成コードの**形**に関する不変条件。フレームサイズ、`rsp` の整合、プロローグ/エピローグの対応、特定の命令を出していないこと |
| **向かない** | **網羅**。いま走査しているのはテストが自分で定義した関数だけで、イメージ内の全 JIT 関数ではない。全関数を回すにはアドレス→関数の逆引き(`disasm_lisp.c` の `d_env_functions_alist`)を Lisp へ出す必要がある |
| **向かない** | **実行時にしか決まらないこと**(GC で動く値、実際の再帰深さ) |
