# 合否の一行は偽造できた —— 3 つの形と、それぞれを今どう塞いでいるか(#205 / T4)

作業日 2026-11-09。基点 `bd6780c`(= `main`)。**QEMU は 1 回も起動していない。**
確かめたことはすべて母艦側(`make test` から走る)で、
対照に使う資料は**合成**である(本物の実機ログは測った機械にしか無く、CI で動かない)。

設計の入力は `docs/investigation/detector-t4-passline.logic.md` と同名の `.refs.md`
(同じ PR で入れた)。issue #205 のコメント「設計(確定版)」が仕様である。

---

## 0. まず正直な前提 —— 「止める」ではなく「在庫を固定する」

**決心した書き手による偽造は止められない。** 合否の一行は結局ただの文字列で、
書ける者は書ける。だから目標を言い換えてある:

> **偶然には偽造できないようにし、意図的にやったら目に見えるようにする。**

実装は「在庫を固定して、増えたら落ちる」形である
(`tools/check_eval_error_budget.py` の予算、`tools/check_jit_bail_lines.py` の印と
同じ考え方)。**件数の照合はこの道具の仕事ではない** ——
それは `tools/check_test_count_ratchet.py`(#204)が段ごとの名簿として持っている。
こちらが見るのは **「合否の一行そのものが信用できるか」** である。

---

## 1. 偽造できる 3 つの形と、今の塞ぎ方

| # | 形 | 以前 | 今 |
|---|---|---|---|
| **(1)** | **部分一致に当てる。** 判定役は成果物の**どこかに** `" 0 failed"` があればよいとしていた。本物の合否の一行が `5 failed` でも、別の行にその文字列を出せば通る | `grep -q " 0 failed" test-results.txt`。行の形も位置も見ていない | **行まるごとの一致にし、位置も見る。** 判定は `tools/check_pass_line.py --verify` の 1 箇所に寄せた |
| **(2)** | **一行を直接書く。** 枠組みを使わず合格の一行を自分で組んで成果物へ書く。**検査 0 件でも合格と言える** | 書く箇所を数えている者が居ない | **在庫を (ファイル, 分類, 件数) で固定した。** 増えても減っても落ちる |
| **(3)** | **集計変数を戻す。** 意図的に出した不合格を `setq` で元の値へ戻す | 同じく数えている者が居ない | **減らす代入だけ**の在庫を固定した。増やす向きは安全側なので数えない |

### 1-1. (1) 判定を行まるごとの一致にした

`tools/check_pass_line.py` の `verify_artifact` が見るのは次の 4 つである:

1. `==== isiki tests: N passed, M failed ====` に**行まるごと**一致する行
2. それが**ちょうど 1 行**であること(1 周 1 本。実機 1 周の記録で確認済み。§5)
3. それが**成果物の最後の非空行**であること(= 報告のあとに書き足されていない)
4. `M == 0` かつ **`N > 0`**(1 件も走っていない成果物を合格にしない)

**判定の口は 3 つに分かれていた**(調査 §A-4)。それが穴の元なので 2 つを 1 箇所へ寄せた:

| 口 | 以前 | 今 |
|---|---|---|
| `tools/run_qemu_milestone.sh`(CI の 12 段とベンチのゲートが乗る) | `grep -q " 0 failed"` | `check_pass_line.py --verify` |
| `Makefile` の `test-qemu` | `grep -q " 0 failed"` | 同じ者を呼ぶ |
| `Makefile` の `test-qemu-no-9p-run` | 件数まで照合 | **そのまま。** この段は合否の一行を出さず、`tools/check_test_count_ratchet.py --stage` が件数で見ている |

### 1-2. (2) 書く箇所の在庫

`tools/check_pass_line.py` の `WRITERS` が唯一の名簿である。
**数字は手で数えていない**(規則 13):`--list` が (ファイル, 分類, 件数) を出し、
食い違えば検査が**次に書くべき数字**を言う。現状の在庫は

```
合否の一行を書く箇所 22(REAL=2 SELF-TALLY=2 PROBE=2 FIXTURE=16)/ 集計を減らす代入 5
```

分類は 4 つだけ:

| 分類 | 意味 | 件数の出どころ |
|---|---|---|
| `REAL` | 本物の集計が書く一行 | 枠組み(`test/lisp/test_framework.lisp`)と C 側の起動スモーク(`src/c/kernel.c`) |
| `SELF-TALLY` | 枠組みが使えない前提の段の自前集計 | `qemu_boot_no_init_signal.lisp` / `qemu_boot_m1_cost.lisp` |
| `PROBE` | 計測プローブの固定文字列。**本物の集計ではない** | `tools/mandel_run.lisp` / `tools/gen_jit_nest_probe.py` |
| `FIXTURE` | **判定役・比較器にかけるための偽の一行**(= 陽性対照。偽造ではない) | 判定役 / 比較器 / 件数照合器 / この道具自身の自己試験 |

### 1-3. (3) 減らす代入の在庫

**非対称性が効く**(調査 §A-2):

- **増やす向き**(`(setq *isiki-test-fail* (+ *isiki-test-fail* 1))`)は
  **不合格を増やすので安全側**。実際に 3 箇所あるが、偽造にならないので数えない
- **減らす向き**(退避値や定数を書く)だけが危ない。該当は **3 ファイル 5 行**で、
  **いずれも正当な後始末**である(陽性/陰性対照が意図的に出した不合格を元へ戻す)

問題は**正当な後始末と偽造が構造的に区別できない**ことなので、在庫を固定した。
4 本目を足すと落ちる。

## 2. 印は成果物ではなくソースに置く(調査の不明点 7 への答え)

**【判断】ソースのその行に、コメントとして置く。** 成果物の中には置かない。

理由: 成果物は**ゲストが書く出力**であり、そこに印を置くと**印そのものが偽造できる。**
検査は母艦側でソースを読むので、印もソース側にあるべきである
(既存の `BAIL-TAG` と同じ作法)。

    PASS-LINE: <REAL|SELF-TALLY|PROBE|FIXTURE> <理由>
    TALLY-RESTORE: <理由>

**複数行にわたる式**(枠組みの `format` は 2 行ある)では、式の途中へコメントを
割り込ませるより安全なので、**直前のコメント行**に置くことも許している。

### 2-1. 印が乱用されないようにしてあること

**印を付ければ何でも通る形にはしていない。** 4 つの縛りがあり、
**どれも `--self-test` の陽性対照で実際に落ちることを確かめてある**:

1. **在庫は (ファイル, 分類, 件数) で固定。** 印を付けても、名簿に無いファイル・
   名簿より多い件数は落ちる(= 「印を付けて 4 本目を足す」は通らない)
2. **`FIXTURE` は自己試験の口を持つファイルだけ。** 試験ファイルや台本が
   自分を「判定役の資料」と名乗れない
3. **置き場所で役を縛る。** `PROBE`/`FIXTURE` は `tools/` の下だけ、
   `REAL`/`SELF-TALLY` は `test/lisp/` と `src/c/` だけ
4. **印には理由を書かせる。** 空の印は落ちる

### 2-2. **印を外すと落ちることを、自己試験が毎回確かめる**

印を付けただけでは「効いている」と言えない。そこで `--self-test` は、
**現物の資料 3 本**(判定役の自己試験 `tools/run_qemu_milestone.sh`、
比較器の駆動側 `tools/jit_dump_identity.sh`、比較器本体
`tools/check_jit_dump_identity.py`)を一時ディレクトリへ写し、
**`PASS-LINE: FIXTURE` の行だけを消して**同じ検査にかける。
3 本とも「印の無い合否の一行がある」で落ちる。

## 3. 一緒に落ちるものと、移行の順序(ここを間違えると自分の対照を壊す)

調査 §9-2 のとおり、**判定役と比較器の自己試験は、偽の合否の一行を自分で作って
判定役にかける。これは正当な陽性対照である。**
厳しくすると**この 3 本も一緒に落ちる。**

だから作業は **「対象外の印を付ける」→「締める」** の順で入れた
(コミットも 2 つに分けてある)。
**逆順でやると、自分の陽性対照を壊したまま「通った」と勘違いする。**

## 4. 計測プローブの最小の形(テンプレート)

**計測プローブを消すのが筋ではない。** 用意しないと次の人がまた偽造する
(調査 §8-4)。現に在庫の 2 本は「判定を通すため」に固定文字列を書いている。

### 4-1. 枠組みが読めるなら、枠組みを使う(これが第一候補)

```lisp
(load "test/lisp/test_framework.lisp")
;; 測る
(defglobal p-t0 (get-internal-real-time))
(defglobal p-result (測りたいもの))
(defglobal p-t1 (get-internal-real-time))
;; **測った値は自分のファイルへ**(成果物は判定の出口なので混ぜない)
(defglobal p-out (open-output-file "/9p/tmp/my_probe.txt"))
(format p-out "#probe ticks=~D result=~S~%" (- p-t1 p-t0) p-result)
(finish-output p-out) (close p-out)
;; **合否は不変条件から出す。** 固定文字列を書かない
(assert-equal t (if (> (- p-t1 p-t0) 0) t nil))
(isiki-test-report)
```

これで件数も合否も**本物**になり、在庫にも入らない(`PASS-LINE` の印が不要)。

### 4-2. 枠組みが使えないなら、自前集計の既存の形に揃える

`test/lisp/qemu_boot_m1_cost.lisp` の `ck` と同じ 4 行を写し、
**1 件 1 行の `#ck` 行**と合否の一行を自分で組む。固定文字列より 1 段良い
(件数が実際の判定から出る)。この形を使うなら:

- 行に `PASS-LINE: SELF-TALLY <理由>` を付ける
- `tools/check_pass_line.py` の `WRITERS` に足す(**理由も同じ場所に書く**。規則 16)
- 常設の段にするなら `tools/check_test_count_ratchet.py` の `COUNTS` にも登録する
  (登録しないと**期待件数 0 として扱われ、縮んでも差が出ない**)

### 4-3. **固定文字列(`PASS-LINE: PROBE`)は在庫が固定されている**

現状 2 本。**3 本目を足すと `make test` が落ちる。**
落ちたときは「名簿を上げる」のではなく、まず 4-1 / 4-2 が採れないかを見ること。

## 5. 確かめたこと / 確かめていないこと(★)

### 5-1. 実行で確かめたこと

- **(1) の穴は実在した。** 旧判定そのもの(`" 0 failed"` の部分一致)に、
  `[NG]` 行へ `" 0 failed"` を出し本物の一行を `5 failed` にした合成資料をかけると
  **通る。** 新しい判定は落とす。
  → 調査 §9-1 / §A-5 が **★ 未検証**としていた「部分一致の穴が実際に通るか」は、
  **母艦側については埋まった**(`--self-test` の「旧判定はこれを通していた」)
- (1)(2)(3) それぞれの陽性対照と、**印を外すと落ちること**(§2-2)
- **合否の一行は 1 本で、成果物の最後の非空行である**ことを、実機 1 周の記録
  (T1 が残した `make test-qemu-all` 1 周のログ、23 本の合否の一行)で確認した。
  段の境界を挟まずに 2 本並んだ箇所は無く、合否の一行の直後は必ず make の出力だった。
  **判定 2・3(「ちょうど 1 行」「最後の非空行」)はこの観測に依拠している**

### 5-2. ★ 未検証のまま残したこと

- ★ **ゲストが実際に偽造の一行を出せるか**は実機で確かめていない。
  (1) の穴は**母艦側の判定で**実測したが、
  「`[NG]` 行に `" 0 failed"` を含む期待値を置いた試験が実機で本当にその行を出すか」は
  QEMU を使うので今回やっていない。**この PR は母艦側だけで閉じている**
- ★ **厳しくした判定が実機 1 周で通るか**は走らせていない(QEMU 禁止の条件下)。
  依拠しているのは 5-1 の記録 1 周ぶんである。
  **新しい判定が落ちるとしたら「成果物の最後の非空行でない」形**で、
  そのときは段ではなく判定の前提(1 周 1 本)が間違っていることになる
- ★ **偽造 (2) の 2 本(計測プローブ)を本物の形へ直してはいない。**
  在庫を固定し、テンプレート(§4)を記録しただけである。
  `tools/mandel_run.lisp` は「旧 `main` と同一のドライバを使う」制約があり
  (調査 §D)、直すと**実機で測り直さないと正しさが言えない**
- ★ 枠組み側に「誰がいつ何件戻したか」を記録させる案(調査 §9-1 の末尾)は
  **やっていない。** ゲスト側の変更が要り、在庫の固定で同じ効果が安く得られる。
  在庫が増えて区別が必要になったら戻る

## 6. 走らせ方

```sh
make check-pass-line             # 在庫の照合(make test から走る)
make check-pass-line-self-test   # 偽造 3 形の陽性対照 + 印を外すと落ちる対照
python3 tools/check_pass_line.py --list    # 在庫を出す(名簿の導出)
tools/run_qemu_milestone.sh --self-test    # 判定役の 5 経路(5 本目が偽造の一行)
```
