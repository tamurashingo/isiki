# エディタの保存に**残る危険**(#218)

> 対象: `apps/editor.lisp`(初版)。基準 main = `42d4a3a`。
> 調査は `docs/investigation/app-editor.{logic,refs,predictions}.md`(§9-1 / §13 / §8-6)。
> **この文書は「直せなかったこと」を書くためにある。** 隠さないために置いた。

## 一行で

**保存の途中で落ちると、元のファイルは戻らない。**
控え(別名)を先に書くので**人が復元できる**ようにはなったが、
**差し替え(安全な置き換え)は組めない。**

---

## なぜ安全な差し替えが組めないのか

普通のエディタは「別名で全部書く → 名前を入れ替える」で保存する。
入れ替えが一瞬で終わるので、どこで落ちても**元か新しいかのどちらか**が残る。

この OS では**その作法が取れない**。理由は 2 つで、どちらも下回りの性質である:

| # | 事実 | 出どころ |
|---|---|---|
| 1 | **書き込み用に開いた瞬間に中身が空になる** | `src/c/mount.c:309-340`(FAT は空ベクタで全体書き換え)/ `src/c/stream.c:282`(9P は `P9_OTRUNC`) |
| 2 | **名前を変える手段も、消す手段も無い** | `src/lisp/fat16.lisp` / `fat32.lisp` に該当の関数が無い。`src/c/p9.c` に `Tremove` / `Twstat` が無い |

1 だけなら「別名で書いてから入れ替え」で逃げられる。
**2 があるので入れ替えができない。** したがって
**元の内容が消えている瞬間が必ずある。**

## いま何をしているか

`%ed-save`(`apps/editor.lisp`)は**この順**で動く:

1. **控え**を別名(`NOTE.TXT` → `NOTE.BAK`)へ書く
2. 控えが書けたときだけ、**本体**を書く

控えが書けなければ**本体を開かない。** 開いてしまうと
「控えも無い・本体も空」という、いちばん悪い状態になる。

### 控えに入るのは「元の内容」ではなく「**保存しようとした内容**」である

ここは誤解されやすいので明記する。

本体を開いた時点で元の内容は失われる(事実 1)。**どうやっても守れない。**
だから控えが守るのは**いま書こうとしている編集結果**のほうである。
本体の書き込みが途中で死んでも、**控えを開き直して別名で保存し直せば編集は救える。**

## **残る危険**(直っていない)

```
元の内容あり
   │
   ├─ 控えを書く ────────────┐  ここで落ちる → 本体は無事。控えが半端に残るだけ
   │                          │
   ├─ 本体を開く ────────────┤  **この瞬間に本体は空になる**
   │                          │
   ├─ 本体を書いている ──────┤  ★ ここで落ちると **本体は空か途中**
   │                          │     → 控えに編集結果が在る。人が手で戻す
   └─ 閉じた(保存完了)
```

**★ の窓は消せない。** 消すには「名前を変える」か「書き込み用に開いても
中身を空にしない」のどちらかが要り、**どちらも下回りに無い。**

### 落ちたときに人がやること

1. `NOTE.BAK` を読む(`cat` でもエディタでも)。**編集結果はここに在る**
2. エディタで `NOTE.BAK` を開き、本体の名前で保存し直す
   —— ただし**その保存も同じ危険を持つ**

## そのほか隠さずに書いておくこと

| 事項 | 内容 |
|---|---|
| **控えの名前が衝突する** | `NOTE.TXT` と `NOTE.DAT` の控えはどちらも `NOTE.BAK` になる。**黙って上書きする。** 避ける方法が無い(消す手段も改名も無いので、空いている名前を探して予約することができない) |
| **控えは消えない** | 保存のたびに `.BAK` が残る。**消す手段が無い**ので、利用者が自分で気にするしかない |
| **末尾の改行が 1 つ増えることがある** | `read-line` は改行を捨てて返すので「末尾に改行がある / 無い」の区別が**読んだ時点で失われる**。保存は必ず各行の後ろへ改行を 1 つ書くので、改行で終わっていないファイルは **1 バイト増える** |
| **★ 復帰文字(CR)は確かめていない** | CRLF のファイルは CR が行の中の 1 文字として残るはずだが、**実機で確かめていない**(調査 §16-2 の不明点がそのまま残っている) |
| **511 文字以上の行があるファイルは開かない** | `cc_read_line` の器は 512 固定で、**溢れた分は何も言わずに捨てられる**(`src/c/stream_lisp.c:504-537`)。「ちょうど 511 文字」と「切り捨てられた」が見分けられないので、**見分けられないものを編集させない**ことにした。開かずに断る |
| **★ 2000 行の上限は測って決めていない** | 使える記憶の総量を測っていない(調査 §16-1)。破綻の点が分かるまでの暫定値である |
| **★ FAT 上の上書きはこの企画の試験では通っていない** | エディタ固有の保存の試験(控え・縮む上書き・2 回続けて)は**母艦共有(9P)**に対して行っている。アプリ専用の円盤へ書くと段をまたいでほかの試験の題材が変わるためである。FAT 側の上書き(#199)は `test/lisp/fat16_test.lisp:651-705` が別に押さえており、エディタは同じ `with-open-output-file` の口を使っている |

## 直すとしたら

**C を触ることになる**(#218 の設計は「C を触らない。新しい口はゼロ」なので
この仕事では入れていない)。要るのはどちらか 1 つ:

- **名前を変える口**(FAT の項目の書き換え + 9P の `Twstat`)。
  これが在れば「別名で書いて入れ替え」になり、★ の窓が消える
- **開いても中身を空にしない書き込み**(追記位置を指定して上書きし、
  最後に長さを切り詰める)。★ の窓は縮むが消えはしない

**前者を勧める。** 後者は「切り詰める前に落ちると末尾にゴミが残る」形の
別の危険を作る。
