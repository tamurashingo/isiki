# AOT の 2 引数直接呼び出しに `*` `/` `<=` `/=` が漏れていた(#128)

> 状態: **実装前の宣言(2026-11-03)。** 実測は §4。

## 1. 見つけ方 — 陽性対照が壊れていたおかげで気づいた

PR #152(A)で「基準値を更新しなくてよい」ことを導くために、
**ベンチの本体が `primitive_multiply2` を呼ぶか**を数えた。陽性対照として
`*` を使う `%%bench-aot-for-swap` を見たら、**呼んでいなかった**。

生成コードを見ると:

```c
/* (+ a b) -> 2 引数版へ直接 */
primitive_add2(__call_arg_5720, __call_arg_5721);

/* (* i 10) -> 可変長版。**cons を 2 つ作って渡す** */
primitive_multiply(os_make_cons(__call_arg_5722,
                   os_make_cons(__call_arg_5723, nil)), env);
```

## 2. 漏れていたのは 4 つ

`transpile.lisp` の `*primitive-fixed-arity-c-names*`(実引数の個数がちょうど
一致する呼び出しを C 関数へ直接 call する対応表)を数えた:

| 演算 | 表にあるか |
|---|---|
| `+` `-` | **ある** |
| **`*` `/`** | **無い** |
| `=` `<` `>` `>=` | **ある** |
| **`<=` `/=`** | **無い** |

**`*` `/` だけでなく `<=` と `/=` も漏れていた。**
対応する C 関数は 4 つとも**存在する**(`primitive_multiply2` /
`primitive_divide2` / `primitive_less_equal2` / `primitive_num_not_equal2`)。
**表に載せるだけである。**

## 3. 測る前の宣言(規則 11・14)

**R-path: AOT のみ。** JIT は `za.c` の別の表を使い、インタプリタは関係しない。

### R-set — **記録されている 29 行と 14 区間は動かない**(断言)

AOT 変換対象のソースでの使用数を数えた:

| 演算 | 使用(上限) | どこに集まっているか |
|---|---:|---|
| `*` | **45** | fat16 15 / fat32 17 / device 6 / partition 4 / transpile 1 / bench_aot 2 |
| `/` | **0** | — |
| `<=` | **14** | — |
| `/=` | **4** | — |

**ベンチの測定対象 10 区分は `*` `/` `<=` `/=` を 1 つも使っていない**
(`bench_aot.lisp` の `*` 2 箇所は `%%bench-aot-for-swap` = M9 の意味論の探り針で
**測定対象外**)。したがって:

- `c/*` `aot/*` `jit/*` `interp/*` の **29 行は動かない**(断言)
- 命令数ゲートの **14 区間は動かない**(断言。`*fix-decl` `/fix-decl` は JIT の経路)

**得が落ちるのは FAT / パーティション / デバイスのセクタ計算**で、
そこには速い記録済みの計測が無い(`test-qemu-perf` は分単位)。

### 代わりに**生成物そのものを計器にする**

2 引数の呼び出しが 1 箇所変換されるごとに、`os_make_cons` が**ちょうど 2 つ**消える
(`os_make_cons(a, os_make_cons(b, nil))`)。したがって次の**関係**が成り立つはずである:

> **Δ`os_make_cons` = 2 × Δ(可変長呼び出しの箇所数)**

絶対値は導けない(45 箇所のうち何箇所がちょうど 2 引数かを数えていない)ので、
**関係を宣言する。** 成り立たなければ、他の何かが変わったということである。

基準(2026-11-03):

| 量 | 値 |
|---|---:|
| `primitive_multiply(` | **86** |
| `primitive_divide(` | **0** |
| `primitive_less_equal(` | **24** |
| `primitive_num_not_equal(` | **6** |
| `os_make_cons(` | **2,266** |
| `lisp_compiled.c` の行数 | **21,311** |

確保量も同じ関係で減る: **1 呼び出しあたり 32 byte**(対 2 個)。

## 4. 実測(2026-11-03)— **宣言した関係が端数なく当たった**

| 量 | 基準 | 実測 | 差 |
|---|---:|---:|---:|
| `primitive_multiply(`(可変長) | 86 | **0** | −86 |
| `primitive_divide(` | 0 | 0 | ±0 |
| `primitive_less_equal(` | 24 | **0** | −24 |
| `primitive_num_not_equal(` | 6 | **0** | −6 |
| **可変長呼び出しの合計** | **116** | **0** | **−116** |
| **`os_make_cons(`** | 2,266 | **2,034** | **−232** |
| 生成物の大きさ | 3,322,183 byte | **3,315,571 byte** | −6,612 |

### 宣言した関係

> **Δ`os_make_cons` = 2 × Δ(可変長呼び出し)**

**−232 = 2 × 116。端数なく成り立った。**

### 分かった副産物: **116 箇所すべてがちょうど 2 引数だった**

可変長版の呼び出しが **0 件になった**ので、AOT 変換対象のソースには
**3 引数以上の `*` `<=` `/=` が 1 つも無い**ことが分かる
(あれば `primitive_multiply(` が残る)。
使用数の上限として数えた 45 / 14 / 4 箇所が、**そのまま全部変換された**
(生成物では `__step` と `__step_fixed` の 2 系統に複製されるので 86 / 24 / 6)。

### 記録されている行は動かない(宣言どおり)

- `make test` **8,551 件 OK / NG 0**
- `make test-qemu` **5,158 件 / 0 failed**(**件数は基準と同じ** = 回帰なし)
- ベンチの 29 行と命令数ゲートの 14 区間は**対象外**
  (測定対象 10 区分が `*` `/` `<=` `/=` を 1 つも使っていない)

**得が落ちるのは fat16 / fat32 / device / partition のセクタ計算**であり、
そこには速い記録済みの計測が無い。実行時の確保量は
**1 呼び出しあたり 32 byte**(対 2 個)減る。

### 絶対値が導けないときは関係を宣言する

「45 箇所のうち何箇所がちょうど 2 引数か」は数えていなかったので、
絶対値は宣言できなかった。代わりに**関係**を宣言した。

> **関係の中では母数を取り違えようがない。**
> このセッションでは「掛ける/割る相手の取り違え」で 5 回外しているが、
> **関係として宣言した 2 回(ここと `interp/loopcost − interp/loop`)は
> どちらも当たっている。**
