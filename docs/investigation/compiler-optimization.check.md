## 方位文書・PR 本文とリポジトリの実態が食い違った点

**規則 15 が想定している形の食い違いが、実際に 4 件見つかった。**

1. **方位文書の検出器一覧に、このトピックブランチに存在しないものが 3 件ある。**
   マクロの前方参照を走査する道具とその make ターゲット、
   およびテスト枠組みのファイル単位件数検査である。
   これらは**別の未マージの作業ブランチにしか存在しない**(そのブランチの PR は open)。
   なお `documents/` 側の調査文書は「この 2 点はあちらのブランチにしかない」と
   正しく書き分けている。**食い違っているのは方位文書だけである。**
   → 方位文書より `documents/` が正しかった実例。

2. **方位文書は「加算・減算の宣言制御によるインライン展開が機能として入った」と
   書いているが、このトピックブランチには入っていない。**
   このブランチにあるのは「宣言に関係なく常に出る高速路」で、
   宣言で入り切りできる形の実装は上記の未マージブランチにある。
   → G4 の判定に直接影響する。

3. **規則 15 の検出器(PR 本文の成果物をマージ後に突き合わせる仕組み)は
   分岐元へマージ済みだが、作業ブランチに取り込まれていない。**
   マージとブランチ作成がほぼ同時刻に起きており、
   分岐元を更新せずに枝を切ったために入っていない。
   **指示書自身が「本作業の前に小さい PR として入れることを勧める」と書いた案が、
   そのとおりマージされたのに、本作業の枝には効いていない。**
   → 本作業の PR 本文はこの検出器の対象にならない。取り込みが必要。

4. **指示書は「寸法の即値を後から埋める仕組みが既にある」と書いているが、
   寸法の即値はその場で定数として出力されている。**
   後から埋める技法そのもの(分岐先の解決)は確かに存在するので、
   「使える」という見通しは正しいが、「すでに寸法に使われている」は成り立たない。
   指示書の完了条件に「後埋めを寸法に使えることを確認した」が別項目で挙がっているので、
   そこは未確認のままという扱いで整合する。

軽微なもの:

- ある調査文書の冒頭注記にある「残り箇所の予算」の数が古い(その後 1 箇所増えている)。
  ただし**増やした理由と性質は検出器側に詳しく記録されており、黙って上げた形ではない。**

## ゴール全体として、何がどれだけ残っているか

### ほぼ残っていないもの

- 計器と検出器の**土台**。両経路・双方向の基準値照合、推定量の校正点、
  断念箇所の自己申告、フレーム内訳、寸法と解体の整合、再帰深さ(間接・直接)、
  出口の数え上げ。多くに陽性対照があり、自己試験として常設されているものもある。
- 案 d の**第 1 段**。これは完了している。

### 大きく残っているもの

1. **案 d の第 2〜6 段**(G1)。本作業の主要部分がそのまま残っている。
   第 2 段(並べ替えだけ、寸法不変)が設計上の要点であり、まだ 1 行も入っていない。
   混在ブートの検証、予備領域の追従の実測、AOT 生成物の同一性確認も残る。
2. **最適化そのもの**(G3・G4・G5)。safety はコード生成に一度も効いておらず、
   乗算・除算のインライン展開と比較演算の型特化も入っていない。
   AOT が宣言を見ていない件は「見ていない」という事実が記録されただけで、
   効かせる / 効かせないの結論は出ていない。
   加えて、加算・減算の宣言制御インライン展開が**未マージの枝に取り残されている**。
3. **性能悪化の直し**(G2)。原因は特定済みだが、直しが入っていないので
   Issue は閉じられない。基準値の最終的な扱いもそこに依存する。
4. **後片付け系**(G6・G7)。どちらも小さいが、内訳を出す / 展開形を揃えるという
   具体的な作業が残っている。
5. **仕様バグの決着**(G8)。片方は「範囲を広げるか、現状で閉じるか」の判断、
   もう片方は「構造の議論を受け入れて閉じるか、回避を戻して試すか」の判断が必要。
6. **検出器の取り込みと確認**(G9)。規則 15 の検出器を作業ブランチへ入れること、
   方位文書の一覧をリポジトリの実態に合わせて直すこと、
   陽性対照が無い検出器を洗い出すこと。
7. **出口**(G10)。仮想機械上の全回帰の実行と、2 つの PR(作業ブランチ → 分岐元、
   分岐元 → main)の作成。

### 優先順の提案(論理のみ)

- **最初に G9 の取り込み漏れを直す。** 本作業は段が多く PR 本文に書くことが多いので、
  本文を検査対象にできる状態にしてから進めるのが指示書の設計どおりである。
  同時に、方位文書の検出器一覧を実態へ合わせる(3 件は別ブランチ、と書き分ける)。
- 次に **G1 の第 2 段**。寸法を変えずに並べ替えだけを行い、数字が 1 つも動かないことを示す。
  このとき「後埋めを寸法に使えるか」を先に確認する必要がある(現状は定数直出し)。
- G2 の直しと G4 は、**未マージの枝(#94)をどう扱うか**を先に決めないと重複する。
  取り込む / 捨てて作り直す / 当面放置する、のどれかを明示的に選ぶべきである。

### 実現済みのマイルストンが他の前提を変えるか（順序の見直しの判断）

**見直しは不要である。** 理由は 3 つ。

1. **実現済みのマイルストンが 1 つも無い。** したがって「前提が変わった」という形の
   順序の崩れは起きていない
2. **M1 を最初に置く理由はむしろ強まった。** 分岐元のローカル参照の遅れを数で確定した結果、
   遅れの中身が「以後のすべての段の PR 本文を検査する仕組み」そのものであることが再確認された。
   これが入っていない状態で段を進めると、本文の検査を受けない PR が積み上がる
3. **上で挙げた 6 件は順序を変えない。** 6 件はいずれも「後ろの段の作業量が減る」方向にしか効かず、
   依存の向きを変えない。とくに寸法を区別して読む手段が既にあることは、
   M4 の内側の順序（計器の拡張を先にするか実寸化を先にするか）を自由にするが、
   M3 → M4 の順序には影響しない

ただし **M2 の中の優先順位について 1 つ提案がある。** M2 のタスクのうち、
「事実の正」の側への転記（死領域の数値、ヒープ量のつまみの不在、整列に必要な分）は
**既に答えが出ているので最も安い**。M2 に入った直後にこれを済ませると、
後続の段がその数値を引用できる状態になる。
一方で生成コードのバイト列比較の手順は **M3 の合否判定そのもの** なので、
M2 の中で最後まで残してはいけない（残すと M3 に入れない）。
