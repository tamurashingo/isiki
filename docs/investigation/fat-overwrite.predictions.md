# 測る前の宣言(規則 11)

**この節は QEMU を 1 回も起動する前に書いた。** 以下は静的な読みから導いた予測であり、
このあとの実測で当たり外れを判定する。**外れたら、外れたことを残す**(規則 6)。

対象: いま main(`800b736`)。`make build` は前景で通済み。
使い捨ての台本は `tmp/ovw_probe.lisp` ほか(git 管理外)。

## 走らせる 2 周

| 周 | 下の仕組み | 円盤 |
|---|---|---|
| 1 周目 | 2 バイト表の FAT | 試験用の使い捨ての写し(16MB) |
| 2 周目 | 4 バイト表の FAT | 試験用の使い捨ての写し(40MB) |

**両方で同じ台本を走らせる。** 下の予測は 2 周とも同じである(= 2 つの仕組みで
同じ結果になる、というのが予測の一部)。

## 予測

| # | 操作 | 予測 | なぜそう読んだか |
|---|---|---|---|
| P1 | 無いファイルを書き込み用に開く | 成功。100 バイト書けて大きさも 100 | 新規は「無ければ作る」側へ行き、切り詰めの段を通らない |
| P2 | **中身のあるファイルを書き込み用に開き直す** | **中断。文面は「書き込み用に開く操作: その道: ファイルを解決できない」** | 切り詰めが全体書き換えで実現されており、全体書き換えは占める塊が減るのを拒む |
| P3 | P2 で中断したあと、ファイルの中身 | 無傷(100 バイトのまま) | 拒む判断は、データにもディレクトリにも触る前に下る |
| P4 | **中身の無い(0 バイトの)既存ファイルを書き込み用に開き直す** | **成功** | 塊が 0 個のままなので「減る」に当たらない |
| P5 | 全体書き換え・同じ塊数のまま小さくする(100→50) | 成功。大きさは 50 になる | 判定は塊の数だけを見ており、バイト数の増減は見ていない |
| P6 | 全体書き換え・塊が増える(100→3000) | 成功 | 塊を足す段がある |
| P7 | 全体書き換え・塊が減る(3000→100) | **拒否(偽を返す)** | 減る場合だけが未実装 |
| P8 | P7 のあと、ファイルの中身 | 無傷(3000 バイトのまま) | 同上 |
| P9 | 読み書き両用で開いて先頭 5 バイトを書き換える | 成功。**大きさは縮まず、末尾に古い中身が残る** | 読み書き両用は切り詰めず、大きさは「今より大きければ伸ばす」しか行わない |
| P10 | 高い層の「配列をファイルへ書く」で中身のあるファイルを上書き(小さく・同じ・大きく **の 3 通りすべて**) | **3 通りとも中断。文面は P2 と同じ** | この層は書き込み用に開く操作をそのまま使うので、書く内容の大きさに関係なく切り詰めの段で落ちる |

## この予測が当たった場合の結論

**仮説 2(下回りが「占める塊が減る書き換え」を受け付けない)が真因。**
仮説 1 の「書き込み用に開く経路に固有」は**鳴る場所としては正しいが、原因ではない**
(その経路だけが切り詰めを要求するために、唯一その経路で露出する)。

P4 が成功することが仮説 1 を「原因」から外す根拠になる
(既存ファイルであること自体が原因なら、空の既存ファイルでも落ちるはずである)。

## 外れ方の意味

- **P2 が成功したら**: 再現条件が別にある(2 周目という時間の要素、または読み込みの順番)。
  その場合は仮説 1 / 2 のどちらでもない
- **P4 が失敗したら**: 原因は「塊が減ること」ではなく「既存であること」。仮説 1 に寄る
- **P7 が成功したら**: 下回りは塊を縮められている。仮説 2 は外れ
- **2 つの仕組みで結果が違ったら**: 経路の違いを名指しし直す必要がある
