## 計画書の読み方

- 各マイルストンは **それ単体で動作し、既存のテストが全て通る状態** で区切っている。途中で壊れた状態を経由しない
- `状態` と `Issue` の欄は後続の作業で書き戻される。第 2 版でもまだ `状態: 未着手` / `Issue: —`
- `実現状況` は実現状況チェック（2026-10-29）の判定の転記。追加調査（2026-10-30）で確定した事実は
  各節の `予測の宣言` と完了条件に反映した
- `R-path`（規則 12）= その変更がどの実行経路（AOT / JIT / インタプリタ）に効くか。実装前に宣言する
- `予測の宣言`（規則 11）= 測定前に宣言する内容。点で書けないものは幅と根拠。
  依拠する前提のうち **未確認のものに ★** を付けている（第 2 版で確認済みになったものは ★ を外した）
- `R-set`（規則 14）= 分解能（3 回測定で約 7）以下の動きでも、「動く行の集合」を事前に宣言すれば検証できる。
  帯は既定 ±20
- 完了条件は「誰が確認しても同じ判定になる」形で書いた。実装方法（関数名・コード）は書かない

## ゴール

### 達成したい状態

`declaim` / `declare` を最適化のヒントとして使い切り、JIT の生成コードを型特化・インライン展開・safety で
速くできる状態にする。あわせて「速くなった / 遅くなったが双方向に見える」計器・検出器を完成させ、
方位文書 §7 の未解決 1〜9 を閉じて、`feature/compiler-optimization` を main へ出せる状態にする。

### 完了条件（G1〜G10）

- **G1 案 d（JIT フレームの実寸化）**
  `ZA_FRAME_TOTAL` 固定ではなく関数ごとの実寸になり、quasiquote（2,496 byte）/ flet-labels（832 byte）を
  使わない関数はその分を確保しない。未使用の穴 296 byte の扱いが決着済み。大小フレーム混在ブートで
  相互呼び出しと末尾呼び出し（サイズの違う関数へ飛ぶ経路）が正しい。検出器（出口の数え上げ /
  `sub rsp`・`add rsp` 整合 / 再帰深さ 間接・直接 / jit-frame-breakdown）が全通過し、各々陽性対照を取っている。
  AOT の生成 C が 1 文字も変わらない。
  **［2026-10-29 に言い直した条件］予備領域と「保証できる最小の深さ」は実寸化では動かないことを確認し、
  記録している。** 導出式の「フレーム 1 段ぶん」は *ありうる最大* の寸法でなければ安全側にならず、
  最大は「まれな領域を全部使う関数」のままなので構造的に縮まない。

  **「呼ばれる場所が 2 つ以上ある小さな関数は展開されない」**。

- 規則 12（R-path）、規則 11（予測を測定前に宣言。点で書けないなら幅と根拠。依拠する前提を列挙し
  未確認のものに ★）、規則 13（件数は導出）、規則 14（R-set）、規則 15（PR 本文の突き合わせ）
- 所要時間（この環境、仮想化支援なし）: ホスト側の門番は秒。配置の内訳と AOT 生成はゲスト不要。
  **AOT 生成物の同一性比較は 1 回 0.86 秒**（2026-10-30 実測）。ゲスト 1 起動は分の単位。

### 構造的に保証されていること（完了条件の根拠に使う）

- フレーム配置は領域の起点と大きさが 1 つの連鎖した定義で、後ろの起点は前から計算される。
  フレーム内の番地参照は **例外なく 3 つの入口** を通り、3 つとも **幅が固定の 32 bit 変位** で機械語を出す。
  **したがって並べ替えは命令数もバイト長も 1 つも変えない**（C-1。M3 の完了条件の根拠）
- 寸法は入口（関数ごとに 1 つまたは 2 つ）でその場で定数を即値として書き出す。後埋めではない。
  既存の後埋め機構は分岐の飛び先（相対距離）専用だが、「埋める場所を配列に覚えて最後にまとめて埋める」形の
  前例はある（共有スタブへの飛び先、自己参照の即値）。上限超過で生成を捨てて解釈実行へ落とす作法も確立（C-1、C-8 の 2）
- **［2026-10-30 確定］末尾の解体命令（`add rsp`）の個数**: 実測の最大は **48**（1 関数のみ。2 位は 14、
  99.6% の関数は 4 以下）。**構造上の上限は 258**（末尾呼び出し 1 件が共有スタブへの飛び越し 1 つを必ず出し、
  その配列上限が 128。解体はその 2 倍 + 出口 2）。
  **既存の 128 の配列にそのまま乗せると、末尾呼び出しが 64 件を超える関数が静かに機械語化されなくなる**
- 末尾呼び出しでサイズの違う関数へ飛ぶとき、**「自分の戻す量 = 呼び先の取る量」に依存している箇所は
  生成コードには無い**。依存しているのは生成コードの外の 2 つ、**残量検査の閾値**と**予備領域の導出式**（C-3）
- フレーム総量は **16 の剰余が 8** でなければならない（呼び出し規約の整列）。
  **いまこれはコメントにしか書かれていない**（C-5 の 1 → M3-T2 で検査化）
- **［2026-10-30 確定］死領域 = 376 byte**（フレーム上端 40 + 引っ越し跡 296 + 退役 8 + 詰め物 32）。
  上端 40 byte はどの記号も対応せず、呼び出し側が毎回自前で確保しているので未使用（**構造から証明済み。
  塗って測る必要は無い**）。うち 8 は整列のために必要なので、**全部外しても予備領域の縮みは最大 368 byte**
- 整数は符号と絶対値で、負のゼロは存在しない（C-5 の 5）。空リストは「対」の表現を持つ（C-5 の 6）
- ベンチの 2 経路は 1 つの真実源から生成される。片方だけ直すと同期検査が落ちる（C-5 の 12）
- **解釈実行の経路を測る行は 1 つも無い。** 解釈実行に費用を足しても検出器は鳴らない（C-7 測定 → M8 で計器を作る）
- AOT 生成物は版管理外のビルド生成物なので、「1 文字も変わらない」の確認は
  **生成 → 退避 → 再生成 → 比較 の手順を自分で作る必要がある**（C-7 測定 → M2-T1）。
  **［2026-10-30 確定］1 回 0.86 秒・ゲスト不要・2 ファイル（`src/c/lisp_compiled.c` と
  `test/c/lisp_compiled_fixture.c`）が 1 回で両方生成される。比較後は生成物の時刻ごと戻すこと
  （戻さないとカーネル全体が作り直される）**

### 検証手段について確定したこと（第 2 版で追加）

- **#94 由来の「命令数の計器」は区間の実行命令数であり、静的なバイト列比較には使えない。**
  並べ替えの「全数字不変」を確かめるには **`JIT_DUMP=1` の関数ごとのバイト列ハッシュ** を使う
  （ビルドの印に `JIT_DUMP_FLAGS` が入っている）→ M2-T7 で手順化し、M3-T3 がそれを使う
- **既存の寸法を読む間接版は、ある 1 つの試験関数の寸法しか読まない。** 期待値に **7480 が直書き**
  （`jit_frame_test.lisp:63`、`jit_rsp_balance_test.lisp:263,264`）。
  混在後は「どの関数の寸法か」を区別して読む拡張が必要 → M4-T8
- **比較演算の特化関数は土台に 0 件**（`less_than2_fixnum` は存在しない）。
  「宣言された型から呼び先が決まる仕組みに乗せる」だけでは足りない → M7-T2
- **陽性対照が確認できていない検出器は 4 件**: `_Static_assert` 群 / `jit-frame-breakdown` の合計一致 /
  `macro-parity`（意図的発火の記録が期待値ファイルのヘッダにしかない）/ `error-escape-gc`
  （手順は PR 本文にあるが未実行）→ M2-T3
- **ヒープ枯渇の再現手段は 2 通りある**（ゼロではない）: ネイティブ = 試験のヒープを 80 KB 以下にすると
  数十秒で到達（現在はハング）/ ゲスト = 上限検査の無い巨大な配列を 1 つ作るだけで即座に到達
  （現在は機械停止。**しかも停止表示が外部へ出ない経路**）。
  **カーネルにヒープ量の定数は無く、変えられるのは仮想機械のメモリ量だけ。**
  足りないのは期待値を見る試験の側で、**スタック側と同型で書ける** → M8-T6

- 分岐元は main より 164 コミット先。分岐元 → main の PR も無い

### 1 関数のコンパイル状態（C-6）

宣言の値・引数方式・即値の記録・巻き戻し点は **コンパイルごとにリセットされるグローバル** で、
**入れ子のコンパイルは想定されていない**。寸法の後埋めの状態も同じ前提に乗る。
**［2026-10-30 確定］入れ子は構造的には起こりうる**（マクロ展開はマクロ本体を解釈実行する）が、
**全マクロ 29 個を走査して展開時に関数を定義するものは無かった**。入れ子になると
**番地の直し一覧が消えて静かに壊れる**。**判定 1 つで歯止めにできる**（「通常は 0 のはず」という前提は
既にコメントに書かれている）→ M4-T1 で具体化する。
