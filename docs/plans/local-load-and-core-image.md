# ディスクから立ち上がる機械にする(local-load-and-core-image)

- 作成日: 2026-11-08
- 対象: `load` のローカルディスク対応(a)と、コアイメージによる起動の短縮(c)
- 事実の正: `documents/` と PR と実測。この計画書は「順序と完了条件」だけを決める
- 経緯: 初期アプリケーションの検討(Genera / Mezzano の同梱物との突き合わせ)から、
  **アプリを配る手段が無い**ことと、**そもそも素のブートで `let` が使えない**ことが出た。
  FASL 相当(ファイル単位のコンパイル済み形式)は **範囲外**とし、(a) → (c) の順で進める
- **2026-11-08 の方針(ユーザー判断)**: `init.lisp` は当初「ISLisp の実装を C ではなく
  Lisp で書き、直しやすくする」ために切り出したものだが、**実装がほぼ完了したので
  起動時に自動で読み込む**。読み込み元は**ファイルではなく、起動イメージに
  ソースのまま埋め込んだもの**とする(**直しやすさは `src/lisp/init.lisp` を
  編集して再ビルドする形で保つ**)

## 決定(2026-11-08、ユーザー判断)

| # | 決定 |
|---|---|
| **D1** | **埋め込みの読み込みに失敗したら boot error として画面に出し、処理を停止する。** 実装は **`os_panic` を使う**(自前の `for(;;)` は書かない。`os_panic` は `hlt` で止まるので「異常停止」と「極端に遅い」を外から区別でき、QEMU 試験では電源断フックで即落ちる。`runtime.c:1472` の教訓) |
| **D2** | **試験のプローブの `(load "src/lisp/init.lisp")` は外す。** 外すことで、試験が「埋め込みが効いている」ことを確かめる形になる |
| **D5** | **(c) の合格線は決めない。** 数値の測定だけ行う(判断は数字を見てから) |
| **D6** | **imm space の消費の許容上限は決めない。** 測って記録する |

> **D5 / D6 を決めないので、G6 と M3 は「合格を判定する」のではなく
> 「数字を出して記録する」段である。** 判断はそのあと別に行う。

## 0. 結論(先に 3 行)

1. **`init.lisp`(1337 行・72,220 byte・マクロ 31 個・`let` を含む)はブート時に読まれない。**
   AOT は `init_aot.lisp`(860 行)まで。**9p の無い実機では `let` が使えない。**
   → **カーネルに埋め込んで起動時に読む**(M1)。これで機械が自立する。
2. **埋め込みに必要な配管は全部ある。** `os_stream_open_string_input`(`stream.h:203`)は
   ポインタと長さを持つだけで**コピーも書き換えもしない**ので、埋め込んだ配列を
   **ゼロコピーで**読める。読む場所も**既に解かれている**:
   `.qemu-test-trigger` の自動 load は、**ブート時スタックでは足りない**ため
   **process 0 のスタック上**で走らせている(`kernel.c:165`)。同じ場所に相乗りする。
3. **JIT の機械語はヒープ番地を 1 つも埋めていない**ので、同じバイナリなら
   コアイメージに **code の fixup は要らない**。動くのはヒープの番地だけである。

### F7 が効く理由

SBCL の FASL は、機械語を読み込んだあと `sb-vm:fixup-code-object` で
`:assembly-routine` / `:foreign` / `:layout` / `:immobile-symbol` 等を埋め、
しかも**コードが動きうるので fixup を残して再適用する**
(`pack-fixups-for-reapplication`)。

IsikiOS は F7 + F9 により、**同じバイナリなら機械語に手を入れる必要が一切無い**。
動くのはヒープの番地だけで、そこは**コピー GC が既に全オブジェクトを走査して
ポインタを書き換える仕組みを持っている**(`gc_copy_value`)。
**再配置器は「定数を足す GC パス」として作れる。**

## リスクと対策

| # | リスク | 対策 |
|---|---|---|
| R1 | **ヒープ先頭が起動ごとに違う**(F6)。生のポインタを含むイメージは成立しない | M4-T3 で方式を決める。(A) 復元時に delta を足す(GC の走査を再利用)/ (B) ヒープ先頭を固定する。**(B) は実機で破綻しうる**ので (A) を本線に置く |
| R2 | **shadow stack は保存できない**(F10) | **安全点で取る**(REPL の入力待ち)。プロセスは復元せず作り直す |
| R3 | `g_imm_space` の中に**ヒープを指す物**があれば、code は無事でも再配置が要る | M4-T2 で確定させる。**「無い」と決める前に測る** |
| R4 | 古い/壊れたイメージが黙って使われる | 版(`ISIKIOS_BUILD_HASH`)とチェックサムの照合を必須にし、**拒むことを陽性対照で確かめる**(規則 8) |
| R5 | **(c) の価値が小さい** | **M3 で測る。** 合格線は決めない(D5)ので、数字を出してから着手を判断する |
| R6 | **FAT の書き込みが遅い**(F12)。数 MB のイメージの保存が現実的でない | **保存は 9p 経由、復元は FAT から読む**で始める。読みは速い(F12)。保存をディスクへ出すのは FAT の書き込み改善(別件)の後 |
| R7 | `load` をマウント経由にすると、9p 前提の相対パスやエラー文面が変わる | M2-T2 で洗い出し、**陰性対照**(既存の 9p の load が無傷)を試験に入れる |
| R8 | **二重 load。** 試験のプローブはほぼ全部 `(load "src/lisp/init.lisp")` で始まる(F19)。埋め込みで既に読まれていると**同じものを 2 回読む**ことになり、31 個のマクロが再定義され、**imm space を二重に食う**(F9 コードページは不滅) | M1-T5 で決める。**プローブ側の `load` を外す**のが本線。外せば「埋め込みが効いている」ことを試験が確かめる形になる |
| R9 | **Immobilized Space の消費。** 毎回のブートで `init.lisp` を JIT するので imm space(16MB)を食う。しかも**不滅**(F9・F18) | M1-T6 で**測る**。食いすぎるなら「AOT へ移せるものを移す」か「ブート時は JIT を抑止する」を検討 |
| R10 | **小さいヒープの試験。** ブート時の確保が増えると `test/c/runtime_test.c` の `SMALL_HEAP_SIZE` 試験(余裕 5KB 未満・症状はハング)やヒープ枯渇の試験に波及しうる | M1-T6 で確認。既知の罠なので**先に疑う** |

## M1: `init.lisp` をカーネルに埋め込み、起動時に自動で読む(G2)

**目的**: **9p が無くても Lisp が全部使える**ようにする。`init.lisp` の編集しやすさは
`src/lisp/init.lisp` を直して再ビルドする形で保つ。

> **新しい機構はほとんど要らない。** 埋め込みを読むストリーム(F14)も、
> 読む場所(F15 = process 0 のスタック)も既にある。**`.qemu-test-trigger` の
> 自動 load と同じ場所に相乗りする。**

### タスク

#### M1-T1: ソースを C の配列へ変換する生成物を作る
`src/lisp/init.lisp` から `src/c/init_lisp_src.c`(配列 + 長さ)を**ビルドで生成**する。
**`lisp_compiled.c` と同じ作法**にする(生成物・gitignore・`Makefile` の依存に入れる)。
C の文字列リテラルではなく**バイト配列**にする(エスケープと長さの上限を避ける)。

#### M1-T2: `load` の輪をストリーム引数の関数へ切り出す
`cc_load`(`load.c:42`)の「read して eval する輪」を `os_load_from_stream(stream, name, env)`
として切り出す。**9p / マウント / メモリの 3 つで共有する。**
`GC_PROTECT(env)` と、フォームごとの `proc->env` の退避・復元・中断の扱いは**そのまま持っていく**
(どれも理由がコメントに書かれている)。

#### M1-T3: 埋め込みを process 0 のスタック上で読む
`os_stream_open_string_input` で埋め込みを包み、M1-T2 の関数へ渡す。
**実行する場所は `process_trampoline_c`**(`.qemu-test-trigger` と同じ。理由も同じ F15/F16)。
**`kernel_main` のブート時スタックで呼んではいけない。**

#### M1-T4: 読めなかったときは boot error で止める(D1 で決定)
埋め込みなので「ファイルが無い」は起きないが、**読み込み中の syntax error や signal** は起きうる。
そのとき**黙って縮退させず、boot error として画面に出して停止する**。

**実装は `os_panic` を使う。自前の `for(;;)` は書かない**
(`os_panic` は `hlt` で止まるので「異常停止」と「極端に遅い」を外から区別できる。
空の `for(;;)` で 33 分のハングに気づけなかった実例が `runtime.c:1472` に記録されている)。
QEMU 試験では電源断フックが働くので、**試験は固まらずに落ちる**。

あわせて、いまコードに残っている「`init.lisp` 未ロード時」の分岐
(`reader.h:35`、`eval.h:56`)が**到達不能になるか**を確かめ、注記を直す(原則 12)。

#### M1-T5: 試験のプローブの `(load "src/lisp/init.lisp")` を外す(D2 で決定)
ほぼ全部のプローブが冒頭でこれを呼んでいる(F19)。そのままだと**二重 load**(R8)になる。
**外す。** 外すことで、**試験が「埋め込みが効いている」ことを確かめる形になる**
(外し忘れた試験があれば、二重 load のぶん imm space が増えるので M1-T6 の数字で気づける)。
外せないものがあれば**理由を書いて残す**。

#### M1-T6: 測る — imm space / ヒープ / 起動 tick
**(c) の見積りはここで出る。合格線は設けない(D5/D6)。測って記録する。**
- **Immobilized Space の消費**(R9・F18)。16MB のうちいくら使うか
- ブート時のヒープ確保量(`room` / `%%heap-used-bytes`)
- **ブートから REPL が入力を受けるまでの tick**(M3 の基準値になる)
- `test/c/runtime_test.c` の `SMALL_HEAP_SIZE` 試験が通ること(R10)

#### M1-T7: 二重定義の整理
`init_aot.lisp`(AOT 済み)と `init.lisp` に同じ名前の定義が無いか確かめる。
あれば**どちらを正とするか**を決めて記録する。

### 完了条件
- **`-fsdev` / `-device virtio-9p-pci` を外した QEMU で起動し、`(let ((x 1)) x)` が通る**
- `make test` と `make test-qemu-all` が通る
- M1-T6 の数字が記録されている(imm space・ヒープ・起動 tick)

## M2: `load` をマウント経由にする(G1)

**目的**: **アプリをディスクに置いて読めるようにする。**
M1 で `init.lisp` は埋め込みになるので、**これは基盤ライブラリのためではなくアプリのため**である。

### タスク

#### M2-T1: `load` を `os_mount_resolve` 経由にする
`load.c` の `os_stream_open_9p_file` 直呼びを、`cc_open_input_stream`(`stream_lisp.c:143`)と
同じ解決に置き換える。**M1-T2 で輪を切り出してあるので、開き方を差し替えるだけになる。**

#### M2-T2: 9p 専用だったことで隠れていた前提の洗い出し(R7)
相対パスの扱い、`LOAD_PATH_MAX`、エラー文面(`os_signal_io_error("load", ...)`)、
`print_load_abort` の出力先。**変わるものを先に名指しする。**

#### M2-T3: 試験
- FAT 上の `.lisp` を `load` できること(`test-qemu` に段を足す)
- **陰性対照**: 既存の 9p 経由の `load` が無傷であること

### 完了条件
`/mnt/...` の `.lisp` が `load` でき、`make test` と `make test-qemu-all` が通る。

## M3: 計測 — 何が遅いのかを数字にする(G6 の土台)

#### M3-T2: 起動全体の基準値

#### M3-T3: 予測の宣言(規則 11)
**M4 に入る前に「コアイメージで何 tick 縮むか」を宣言する。** 外したらそこで方式を見直す。

### 完了条件
内訳の数字が出て記録されている。**合格線は設けない(D5)**ので、
**この数字を見てから (c) の着手を別に判断する。**

## M4: イメージの設計(調査。G3 の前提)

### タスク

#### M4-T1: 保存すべき状態の棚卸し
- ヒープの**生存集合**(GC を 1 回走らせた直後の From 空間)
- `g_imm_space` の**使用部**(JIT コードページ + imm スロット)
- `.bss` のルート(F10 の一覧 + スロットプール + JIT の記録: `g_jit_used`、スロット計数、関数セルキャッシュ)
- 関数セルの連結リスト(`runtime.c:3510` が走査しているもの)
